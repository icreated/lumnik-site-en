The supplier file sent to EDI: ASCII, upper case, 35 characters, a stable identifier.

Purchasing feeds an EDI platform that requires names in ASCII, upper case, 35 characters at most, and one identifier per supplier. The ERP export has accents, long legal names, inactive suppliers, and an id column holding N/A, 0 or nothing. The EDI's constraint is declared once in the manifest.

The file in EDI format, ids left as they came

filter-where keeps active suppliers; map-columns renames the FOURN_* columns; defaults puts FR in an empty country. In the cell tier, remove-diacritics then upper write ELECTRICITE MENARD; regex-replace turns & into ET and replaces the punctuation the EDI refuses; truncate cuts at 35. to-uuid with on-invalid: keep leaves N/A and 0 as they are, to look at them before choosing.

The chosen rule: empty what is wrong, derive what is missing

N/A and 0 are not identifiers: on-invalid: "null" empties and counts them. A missing id is derived from the supplier code by generate-from: F0004 and F0007 get one. It is not another system's id: it joins to nothing else, it is the EDI's key. The rule change replaces four rows, which the run reports as removed.

Limits

  • truncate cuts without warning: F0001 and F0005 carry the same 35-character name; only their codes tell them apart.
  • A derived id joins to no other system.
  • After a rule change, the run reports the old versions of the changed rows as removed.
  • Synthetic suppliers.
