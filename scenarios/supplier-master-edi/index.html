The supplier file goes to EDI in ASCII with a stable id

Goal Send EDI the suppliers in the form it requires, with an id that does not change.

Purchasing's EDI platform requires names in ASCII, upper case, at most 35 characters, and one id per supplier. The ERP's export has accents, long company names, inactive suppliers, and ids that read N/A, 0 or nothing.

  • names put in the EDI's form;
  • N/A and 0 emptied and counted, a missing id derived from the code;
  • the next day, the same ids.

apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-suppliers-b  connector_type: csv-file  scopes: [purchasing-b]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/supplier-master-edi/b/suppliers.csv  parser:    delimiter: ";"  after_process: none  mapping:    dataset:      - filter-where: { column: ACTIF, equals: "O" }        # inactive suppliers out, counted    row:      - map-columns:          rename: { FOURN_CODE: code, FOURN_NOM: name, ACTIF: active, EXT_ID: ext_id, PAYS: country }      - defaults: { country: FR }                            # an empty country is France    cell:      - remove-diacritics: { columns: [name] }               # Électricité -> Electricite      - upper: { columns: [name] }      - regex-replace: { column: name, pattern: "&", replacement: " ET " }      - regex-replace: { column: name, pattern: "[^A-Z0-9 ]", replacement: " " }   # what the EDI refuses      - regex-replace: { column: name, pattern: " +", replacement: " " }      - clean: { columns: [name], strip: true }      - truncate: { column: name, length: 35 }               # the EDI's hard limit      - to-uuid: { column: ext_id, on-invalid: keep }        # look first: N/A and 0 left as they came

Purchasing · EDI

Suppliers go to EDI.

Every night, from the ERP.

Eight suppliers, six active

The problem

EDI requires its own form.

  • ASCII, upper case, 35 characters.
  • One id per supplier.

What is not changed

The ERP stays as it is.

  • Its export, accents included.
  • No fix at the source.

The trap

Ids that are not ids.

  • N/A, 0, or nothing at all.
  • A random id changes every night.

What had to be written

to-uuid: { generate-from: code }

One line.

  • The same code gives the same id.
  • Wrong values are emptied and counted.
  • A 43-line scenario, two manifests.

The next day

The same ids.

  • One more supplier gets its own.
  • No row removed.

The limit

Cutting at 35 can merge two names.

  • Only their codes tell them apart.
