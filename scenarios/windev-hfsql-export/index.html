WinDev: the client export, with real dates and a real Active flag.

Goal Read the client file a WinDev application exports, and turn it into columns a question can use.

A WinDev application exports its clients with HExportCSV. The file is reconstituted from PC SOFT's documentation.

  • read as it is: six clients, but all text, dates 20190312, Actif 0 or 1;
  • three transformers: the dates as dates, the credit as a number, Actif as a real boolean;
  • a question in SQL: the active clients with no purchase since October.

Client.csv, as HExportCSV writes it

What PC SOFT's documentation says: a comma between values, and the item names on the first line. What a WinDev application commonly writes, though the docs do not say so: Windows-1252, dates AAAAMMJJ, flags 0 or 1.

Dates, an amount, a real boolean

The same file, a second connector: parse-date with yyyyMMdd, parse-number, parse-boolean (#1760). The columns take their type when the table is created.

  • cree_le, dernier_achat: date
  • encours_autorise: numeric
  • actif: boolean
  1. 1
    The question

    Active clients with no purchase since October: WHERE actif AND dernier_achat < DATE '2026-10-01'.

What this step proves

A WinDev export becomes a table to question.

manifests/20-clients-typed.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-windev-a  connector_type: csv-file  scopes: [sales-a]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/windev-hfsql-export/a/Client.csv   # the same export  after_process: none  mapping:    row:      - map-columns:          rename: { IDClient: id_client, NomClient: nom, Ville: ville, DateCreation: cree_le,                    DernierAchat: dernier_achat, Actif: actif, EncoursAutorise: encours_autorise }    cell:      - parse-number: { column: id_client, integer: true }      - parse-date: { column: cree_le, formats: [yyyyMMdd] }          # HFSQL writes a date AAAAMMJJ      - parse-date: { column: dernier_achat, formats: [yyyyMMdd] }      - parse-number: { column: encours_autorise, decimal-separator: "." }      - parse-boolean: { column: actif }                              # 0 / 1

The problem

No database readable from outside.

  • HFSQL has no JDBC driver.
  • The application can export its files.

What is not changed

The application stays as it is.

  • Its existing export.
  • No module, no access to its database.

Read as it is

Six clients, but all text.

  • The dates: 20190312.
  • Actif: 0 or 1.

What had to be written

parse-date: { formats: [yyyyMMdd] }
parse-boolean: { column: actif }
