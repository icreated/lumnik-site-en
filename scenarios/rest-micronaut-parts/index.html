Micronaut: the stores' parts read in three requests

Goal Read every spare part of a Micronaut service through its API, even while the stores work in it.

A real Micronaut 4.7 and 130 fictional parts, served as the repository's Page.

  • fifty per page: all 130 in three requests, the total checked;
  • a part deleted mid-read: the total moves, the list is read again, nothing lost.

All 130 parts in three requests

pagination: { kind: micronaut, size: 50 }. The hub asks ?page=0&size=50, reads content and compares the rows read with totalSize.

  • size: the page size asked
  • stops once the rows read reach totalSize (#1800)
  • 130 of 130

A part deleted: the list is read again

Ten per page, one request a second. While the list is read, PCE-0001, already read on page 0, is deleted. Every later part moves up one place. totalSize moves from 130 to 129: the hub reads the list again from page 0 (#1796).

  • default_rate_limit: one request a second
  • IN 189: the first read, then the second
  • all 129 left are in the table

Limits

  • Micronaut serves at most 100 rows per page: a larger size is cut without a word. Declare a size of 100 or less.
  • A deleted part stays in the hub's table: a full read adds and updates, it does not erase.
  • IN counts the rows read twice; the upsert keeps one.
  • 130 fictional parts, written when the service starts.

Stores · parts

The parts live in a Micronaut service.

Every one must be read, through its API.

Micronaut 4.7, 130 parts

The problem

The API hands the list out in pages.

  • A Micronaut Data Page.
  • The stores keep working meanwhile.

What is not changed

The service stays as it is.

  • Its controller returns the Page as is.
  • No module, no setting.

The trap

Micronaut 4 sends no page count.

  • Every page carries totalSize: 130.
  • totalPages is absent.

What had to be written

pagination: { kind: micronaut, size: 50 }

One line.

  • The hub stops once it has read totalSize.
  • Three requests for 130 parts.
  • A 22-line connector.

While it is read

A part deleted: the list is read again.

  • The total moves from 130 to 129.
  • All 129 left are there.

What was fixed

Two gaps found, two fixes.

  • The total checked on every page (#1796).
  • No empty page at the end of a read (#1800).
