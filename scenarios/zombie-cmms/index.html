The zombie system: thirty years of work orders, the box switched off, the hub still answers.

A CMMS replaced years ago stays on for a handful of compliance reads a year: the licence, the box, and the one person who can restart it. lumnik reads it one last time, archives what it read under a single digest, then the box is switched off. The next run says why it fails, the pause stops the schedule, and the hub gives back the same bytes as before.

The same row, the same digest, the archive kept

Without the CMMS, the hub returns the same row for WO-001234 and the same SHA-256 for the snapshot. A second delivery of the archive is refused: the delivered file is never replaced.

  1. 1
    Same bytes

What this step proves

The data outlives the box that held it.

Limits

  • A connector whose source is switched off fails at every slot until it is paused; the hub does not pause it by itself.
  • lm source jdbc discover still quotes the driver's own message.
  • Retention on the bucket (object lock) belongs to the store, not the hub.
  • Simulated CMMS and bucket; synthetic data.
