The aged balance trapped in a print file

Goal Turn a paginated accounting print file into receivables per invoice, keeping the right client across page breaks and dropping headers and totals.

Accounting prints its aged balance to a spool file.

  • a header on each page;
  • a client, its invoices below, a total;
  • a client's invoices sometimes run onto the next page.

Credit control wants each invoice with its client.

A printed report, without its layout

The connector reads the report as printed.

  • lines: true: one report line = one line read, columns by position
  • filter-where: keeps client lines (411…) and invoices (FA…) only
  • regex-extract: cuts piece, dates, balance and days late
  • parse-date, parse-number: 28/07/2026 becomes a date, 1 840,20 a number
  1. 1
    10 lines

    Layout and totals, counted in SKIPPED.

  2. 2
    Why this filter

    Page headers and totals are not receivables.

What this step proves

A report made for the printer reads as a table.

manifests/10-aged-balance.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-agedbal-b  connector_type: csv-file  scopes: [credit-b]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/aged-balance-print/b/*.lst   # the accounting system's print spool  parser:    lines: true                    # a printed report: one line per row, columns by position  after_process: none  mapping:    dataset:      - filter-where: { column: line, regex: "411.*| {10}FA.*" }   # a client's header, an invoice; page headers and totals are not    cell:      - regex-extract: { column: line, pattern: "^(411\\S*)\\s+(.+?)\\s*$", groups: { 1: client_code, 2: client_name } }      - regex-extract:             # an invoice: piece, invoice date, due date, balance, days late          column: line          pattern: "^ {10}(FA\\S+)\\s+(\\d{2}/\\d{2}/\\d{4}) (\\d{2}/\\d{2}/\\d{4})\\s+([\\d ]+,\\d{2})\\s+(\\d+)\\s*$"          groups: { 1: piece, 2: invoice_date, 3: due_date, 4: balance, 5: days_late }      - parse-date: { column: invoice_date, formats: ["dd/MM/yyyy"] }      - parse-date: { column: due_date, formats: ["dd/MM/yyyy"] }      - parse-number: { column: balance }      - parse-number: { column: days_late, integer: true }      - fill-down: { columns: [client_code, client_name] }   # the client, on the invoices under its header — across a page break

Limits

  • A line dropped by filter-where carries nothing: the filter must keep the client lines.
  • The entity is keyed by the printed line: an invoice reprinted identically is the same row.
  • Synthetic file, fictitious clients and invoices.

Credit control · printed report

Which client is this invoice for?

The aged balance exists, but only printed.

A spool file: page headers, clients, invoices, totals.

Synthetic file, fictitious clients

The problem

The page break cuts a client in two.

  • Page 1: the client and two invoices.
  • Page 2: three invoices, no client.
  • Credit control retypes the report.

Nothing is changed

The report stays as printed.

  • lumnik reads each line.
  • It drops layout and totals.
  • It carries the client onto its invoices.

What it took to write

- fill-down:
    columns: [client_code, client_name]

The client carries down onto its invoices.

The whole scenario fits in 2 declaration files, 46 lines.

The result

12 invoices, each with its client.

  • 411ANSE: 5 invoices over 2 pages, 8,957.30.
  • The printed totals found again.
  • FA26-0644: 85 days late.

The limit

The filter must keep the client lines.

  • A dropped line carries nothing.
  • An invoice reprinted identically is the same row.
