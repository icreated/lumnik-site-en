One rule, three conditions

The Process reacts to a CRITICAL, DECLARED, UNASSIGNED row; it emits one decision.

  1. 1
    Precise

    Calibration rows never match all three.

  2. 2
    Readable

    The message names the incident, the equipment, the line.

What this step proves

One decision, only one.

manifests/30-unassigned-critical-process.yaml
apiVersion: apps.lumnik.io/v1kind: Processmetadata:  name: scenario-gmao-critical-unassignedspec:  scope: maintenance  on:    event: data.row.changed    table: connector.t_scenario_gmao_incidents  when:    - severity=CRITICAL    - status=DECLARED    - technician_id=UNASSIGNED  emit:    type: decision.gmao-critical-unassigned    message: "Critical incident {incident_id}: {equipment_name} stopped on {line_name}; no technician is assigned"

Limits

  • Read-only; no assignment written back to the CMMS.
  • The Process flags; it does not dispatch or remind anyone.
  • Dormancy threshold declared, dormancy alert not shown.
  • The transition row is checked during the replay; no lm command reads it yet.
  • Synthetic data.
