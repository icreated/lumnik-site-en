HPLC: an impurity over its limit in the injection report

Goal Read the injection reports an HPLC exports, with their glued units and decimal commas, and be told when an impurity exceeds its specification.

An HPLC's acquisition software exports one report per injection: UTF-16, a header block, then the peaks.

  • csv-file reads it line by line and carries the sample onto each peak;
  • regex-extract cuts each value from its unit: 0,21% becomes 0.21 and %;
  • an impurity above 0.15 %: one decision.

The sample on each peak, the unit apart

lines: true reads the report line by line. A regex per line kind:

  • the header lines give sample, instrument, injected_at
  • a peak line gives the value and its unit, in two columns
  • fill-down, reset at each Report line: one report never leaks into the next
  1. 1
    Why not parse-number alone

    It removes currency signs and spaces, not min or %. The regex cuts the unit off first; parse-number then reads the decimal comma.

What this step proves

A report made for print becomes one row per peak, typed.

manifests/10-injection-reports.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-chrom-a  connector_type: csv-file  scopes: [qc-hplc-a]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/chromatograph-report/a/*.csv   # the folder the acquisition software exports to  parser:    lines: true                    # a report, not a table: a header block, then the peaks  after_process: none  mapping:    cell:      - regex-extract: { column: line, pattern: "^([^;]+);", groups: { 1: field } }      # the header block: one key;value per line      - regex-extract: { column: line, pattern: "^Sample Name;(LOT \\S+)", groups: { 1: sample } }      - regex-extract: { column: line, pattern: "^Injection Date;(.+)$", groups: { 1: injected_at } }      - regex-extract: { column: line, pattern: "^Instrument;(.+)$", groups: { 1: instrument } }      - regex-extract: { column: line, pattern: "^Method;(.+)$", groups: { 1: method } }      # a peak: the value and its glued unit, cut apart      - regex-extract:          column: line          pattern: "^(\\d+);([\\d ,]+)(min);([^;]+);([\\d ,]+)(mAU\\*s);([\\d ,]+)(%)$"          groups: { 1: peak, 2: rt, 3: rt_unit, 4: peak_name, 5: area, 6: area_unit, 7: amount_pct, 8: amount_unit }      # the report's header, on each of its peaks; a new report starts empty      - fill-down: { columns: [sample, injected_at, instrument, method], reset-when: { column: field, in: [Report] } }      - parse-number: { column: rt, decimal-separator: "," }      - parse-number: { column: area, decimal-separator: "," }      - parse-number: { column: amount_pct, decimal-separator: "," }      - parse-date: { column: injected_at, formats: ["dd/MM/yyyy HH:mm:ss"] }

The specification's limit

The Process listens on the report's table.

  • peak_name~Impurity: the impurity peaks
  • amount_pct>0.15: above the limit, not on it
  • key: sample, the decision carries the lot
  1. 1
    Applied after the first drop

    A Process judges new rows only. The first six reports are within specification.

What this step proves

A specification limit is declared on the columns read from the instrument.

Limits

  • The table keeps every line of the report, header lines included: a rule reads the peaks by their columns.
  • One limit for every impurity: a limit per impurity is one Process per impurity.
  • The regex expects these three units; another unit leaves the line uncut, and the rule does not see it.
  • Synthetic lots, peaks and amounts.

Laboratory · HPLC

The results sit in the instrument's reports.

One file per injection, made to be printed.

UTF-16, 1 532 117,2mAU*s, 0,21%

The problem

LOT 26-0459: impurity B at 0,21 %.

  • The limit is 0,15 %.
  • The report is read by eye, when it is read.

What is not changed

The acquisition software stays as it is.

  • Its own export, in its own folder.
  • No script, no conversion by hand.

What had to be written

pattern: "([\\d ,]+)(%)"
fill-down: { reset-when: Report }

One regex per line kind, one fill-down.

  • The unit in its own column.
  • A Process: impurity above 0.15 %.

The result

One decision, LOT 26-0459.

  • LOT 26-0461 sits on 0,15 %: not above.
  • 36 peaks, 0 cell error.
