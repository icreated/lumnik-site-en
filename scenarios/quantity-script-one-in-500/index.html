One unexpected value in 500 as a dead letter and the other 499 written

Goal Keep one unexpected line from stopping the other 499, and keep it visible.

A goods receipt typed by hand: 500 lines, quantities like « 12,5 kg » or « 3 pce ». An operator's Kotlin script reads them. Line 317 says « env. 4 kg ».

  • version 1: the run fails and writes nothing;
  • version 2: the value declared unreadable;
  • 499 lines written, line 317 a dead letter.

The operator declares unreadable what it cannot read

Version 2 calls unreadable for any unknown form, instead of guessing.

  • the hub counts the cell
  1. 1
    unreadable

    Counted, never guessed.

What this step proves

A script can say "I cannot read this value" without stopping the run.

manifests/quantity-v2.kts
// Operator-provided: reads a quantity written "12,5 kg" or "3 pce" into a number and a unit.// A quantity in any other shape is declared unreadable: counted, never guessed.@Suppress("UNCHECKED_CAST")val cells = bindings["cells"] as MutableMap<String, Any?>val m = Regex("(\\d+(?:,\\d+)?) (kg|pce)").matchEntire((cells["quantity"] as String).trim())if (m == null) {    (bindings["unreadable"] as Runnable).run()} else {    cells["qty"] = m.groupValues[1].replace(',', '.')    cells["unit"] = m.groupValues[2]}

Limits

  • A failing script's message gives the script's line, not the file's: a script that declares the value unreadable is what tells which line is the problem.
  • The dead letter names the kotlin hook, not a column: a script can write several cells.
  • Synthetic lines.

The problem
