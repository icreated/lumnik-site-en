The wrong bar code caught at import: an operator-provided Kotlin script, named by the manifest.

A catalogue export carries EAN-13 codes, some of them wrong. No built-in transformer computes a check digit. The hub's operator drops a Kotlin script into the hub's hooks directory; the manifest names it and carries no code. A draft that does not compile is refused at validate, with its line and column.

// Operator-provided: checks an EAN-13 bar code and says why one is wrong.@Suppress("UNCHECKED_CAST")val cells = bindings["cells"] as MutableMap<String, Any?>val ean = (cells["ean"] as? String)?.trim().orEmpty()cells["ean_status"] = if (!Regex("\\d{13}").matches(ean)) {    "malformed"} else {    val sum = ean.take(12).mapIndexed { i, c -> (c - '0') * (if (i % 2 == 0) 1 else 3) }.sum()    if ((10 - sum % 10) % 10 == ean[12] - '0') "valid" else "wrong-check-digit"}

Every bar code checked at import

The manifest names the finished script. The run reads the 10 products; the script computes each EAN-13 check digit and writes its verdict in an ean_status column. Two wrong check digits and one 12-digit code stand out.

  1. 1
    7 valid

    The check digit matches.

  2. 2
    2 wrong check digits

    One control digit is off.

  3. 3
    1 malformed

    12 digits instead of 13.

What this step proves

A business rule no transformer has is added without touching the hub.

Limits

  • A script runs with all of the hub's rights: only the operator can install one.
  • A replaced script applies from the next batch, never mid-batch.
  • The script runs on CSV imports.
  • Synthetic catalogue, codes under the 200 prefix reserved for in-store use.
