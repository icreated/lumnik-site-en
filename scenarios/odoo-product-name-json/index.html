Odoo read from its PostgreSQL: the product name is a JSON

Goal Read the products of a real Odoo 18 straight from its database and get each product's French name, without writing anything in Odoo.

Since Odoo 16 a translated field is one JSON per row, one key per language. Every report written against the old text column broke. An integrator reading Odoo's database meets it at product_template.name.

  • the name lands as JSON text, every language kept
  • promote reads the fr_FR key into a column of its own, with en_US as the fallback
  • the question in natural language gives the four French names

The name lands as JSON, its French key as a column

A real Odoo 18 runs in Docker. The products are created through its XML-RPC API. The connector reads product_template with a read-only login.

  • rename: id is a hub column, it arrives as product_tmpl_id
  • name: a jsonb column lands as TEXT, the JSON as it is
  • promote: the $.fr_FR key becomes the name_fr column
  • fallback: $.en_US for a product never translated, Odoo's own rule
  1. 1
    Odoo untouched

    Nothing is written in Odoo's database.

  2. 2
    Every language

    The name column keeps the whole JSON.

What this step proves

The language is declared at the door, in the manifest.

manifests/10-product-template.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-odoo-products-a  connector_type: jdbc-generic  scopes: [odoo-a]spec:  connection:    url: jdbc:postgresql://host.docker.internal:55433/scen    user: lumnik_reader    password_env: SCENARIO_ODOO_A_DB  source:    tables:      - name: product_template        schema: public        mode: full        pk_columns: [id]        rename: { id: product_tmpl_id }   # id is one of the hub's own columns        target: odoo_product_template_a   # connector.t_odoo_product_template_a, its own hub table        promote:          - name: name_fr                 # the French name, in a column of its own            column: name                  # Odoo 16+: {"en_US": …, "fr_FR": …}            path: $.fr_FR            fallback: $.en_US             # never translated: the English name, as Odoo shows it            type: text

Each product's French name

The question is asked as a salesperson types it. Ask reads the name_fr column.

  • Chaise de bureau, Bureau assis-debout, Lampe de bureau
  • CABLE-04, never translated: USB-C cable, as Odoo shows it

Limits

  • The language is written in the manifest: the hub never picks it from the reader.
  • Before icreated/lumnik#2122 the question abstained, and the path was a view in Odoo's database, written by the DBA (data/view.sql).
  • Odoo Online does not open its database: it is read through its JSON-2 API (odoo-json2-partners).
  • Four synthetic products.
