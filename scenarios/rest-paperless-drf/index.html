Paperless-ngx: correspondents added and deleted while they are read

Goal Read every correspondent of a Paperless-ngx archive through its API, without losing one when the list changes mid-read, and be warned when it never stops changing.

A real Paperless-ngx 2.13 and 100 correspondents, read ten per page.

  • quiet: all 100, each page's count checked;
  • a correspondent deleted mid-read: the pages shift, the list is read again;
  • new correspondents all the time: the run refuses to call itself complete.

All 100 correspondents in one line

pagination: { kind: drf-page }. The hub follows next, reads results and compares the rows read with the count.

    A witness

    If the hub reads fewer rows than the count declares, the run fails instead of calling itself complete.

Limits

  • A deleted correspondent stays in the hub's table: a full read adds and updates, it does not erase.
  • The second read counts the rows read twice in IN; the upsert keeps one.
  • 100 fictional correspondents, created by the script.

Paperless-ngx 2.13, 100 correspondents

The problem

The API hands the list out in pages.

  • Ten per page, numbered.
  • Meanwhile, the team works.

What is not changed

The archive stays as it is.

  • Its API, a reading account.
  • No module, no setting.

The trap

A deletion shifts the pages.

  • A correspondent on page 1 disappears.
  • Another one lands on no page.

What had to be written

pagination: { kind: drf-page }

One line.

  • Each page's count is checked.
  • If it moves, the list is read again.
  • A 27-line connector.

When it never stops

The run fails, it does not lie.

  • The list moves again on the second read.
  • The message gives both totals.

What was fixed

One gap found, one fix.

  • Before: Completed, a correspondent missing.
  • Now: read again, or refused (#1771).
