NestJS: a ticket deleted mid-read shifts the pages

Goal Read every ticket of a NestJS service through its API, or the open ones only, without losing one when support deletes a ticket mid-read.

A NestJS service on nestjs-paginate and 130 tickets, 97 of them open.

  • all: the 130, following the next link;
  • open only: the filter follows every link, 97 read;
  • a ticket deleted mid-read: the total moves, the list is read again.

The filter follows every next link

The same connector, with filter.status=$eq:open in the path. nestjs-paginate puts the filter back into every next link: the hub adds nothing.

  • 97 tickets, all open
  1. 1
    Why filter at the source

    The service returns only what is read: no closed ticket reaches the hub.

What this step proves

A ticket deleted: the list is read again

Ten per page, one a second. During the read, Ticket 001, already read on page 1, is deleted. Every later ticket moves up one place: one ticket is on no page. meta.totalItems goes from 130 to 129, so the hub reads the list again (#1794).

  • default_rate_limit: 1/s, one page a second
  • IN 189: the first read, then the second
  • the 129 left are all in the table
  1. 1
    Before the fix

    The preset did not read meta.totalItems: the run said Completed with a ticket missing.

What this step proves

A list that moves is no longer half-read in silence.

Limits

  • A deleted ticket stays in the hub's table: a full read adds and updates, it does not erase.
  • The second read counts the rows read twice in IN; the upsert keeps one.
  • 130 fictional tickets, in the service's memory.

Support · tickets

The tickets live in the support service.

Every one must be read, through the API.

NestJS 11, nestjs-paginate, 130 tickets

The problem

The API hands the list out in pages.

  • Each page gives the link to the next.
  • Meanwhile, support works.

What is not changed

The service stays as it is.

  • Its API, as the team wrote it.
  • No module, no setting.

The trap

A deletion shifts the pages.

  • A ticket on page 1 disappears.
  • Another one lands on no page.

What had to be written

pagination: { kind: nestjs }

One line.

  • The next link is followed.
  • Each page's total is checked.
  • A 21-line connector.

A filter

Open tickets only.

  • The filter is written in the path.
  • Every next link keeps it: 97 read.

What was fixed

One gap found, one fix.

  • Before: Completed, a ticket missing.
  • Now: the list is read again (#1794).
