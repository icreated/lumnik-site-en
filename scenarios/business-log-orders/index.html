Yesterday's log, read as a source: which orders the errors hit.

Customers call: their order "never went through". The server writes a plain-text log, one file per day. The hub reads it line by line, keeps the warnings and errors, pulls out the order, and joins it to the customer and status it already holds. A business log, not a monitoring tool.

Yesterday's log, one line per row

parser: lines: true reads each line whole, with no delimiter and no quotes. filter-where keeps WARN and ERROR by reading the raw line, since it runs before the cells. INFO lines, stack-trace lines and a line that opens a quote it never closes are skipped and counted. regex-extract pulls out the time, level, server, message and order; parse-date reads the milliseconds in Paris time.

apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-app-log-b  connector_type: csv-file  scopes: [support-b]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/business-log-orders/b/app.log  parser:    lines: true                          # one line = one row, in a column named `line`  after_process: none  mapping:    dataset:      # Runs before the cells exist: it reads the raw line. Keeps WARN and ERROR; INFO and stack traces are skipped.      - filter-where: { column: line, regex: "^\\S+ \\S+ (WARN|ERROR) .*" }    cell:      - regex-extract:          column: line          pattern: "^(\\S+ \\S+) (\\w+)\\s+\\[([^\\]]+)\\] (\\S+) - (.*)$"          groups: { 1: logged_at, 2: level, 3: server, 4: logger, 5: message }      - regex-extract: { column: message, pattern: ".*\\b(CMD-\\d+)\\b.*", groups: { 1: order_no } }      - parse-date: { column: logged_at, formats: ["yyyy-MM-dd HH:mm:ss,SSS"], zone: Europe/Paris }      - truncate: { column: message, length: 120 }

Limits

  • A business log, not a monitoring tool: one file per day, read whole; no tailing, no retention.
  • A stack trace is not attached to its error: its lines are skipped and counted.
  • Synthetic log and orders.
