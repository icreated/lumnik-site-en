An unreadable amount does not get in: the invoice waits, fixed at the source.

A supplier-invoice export carries two mistyped amounts and a test invoice. Instead of writing invoices without an amount, the hub sets them aside with the row as it was read. The test invoice is discarded, the source is fixed, and each letter is closed by the run that brought the right row.

The CSV connector declares on-error: dlq on the amount. FA-2025-0013 holds 1.250.00 and FA-2025-0027 holds 87.5O: the amount cannot be read, so the invoice goes to the dead letters instead of being written without an amount. The test invoice has no supplier: validate-row refuses it.

What this step proves

Every invoice set aside has a known end: replayed by a named run, or discarded.

Limits

  • on-error applies to CSV connectors; dlq is refused beside split-row.
  • The hub checks the named run could have carried the row (same connector, completed, later), not that it wrote it.
  • Synthetic invoices.
