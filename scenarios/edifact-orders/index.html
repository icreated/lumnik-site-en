An EDIFACT ORDERS message: one line, split into segments, the escaped apostrophe kept.

Retail and industry still exchange EDIFACT: a buyer's ORDERS message, often written on one single line, its segments ended by an apostrophe, its elements split by + and :. An apostrophe in a label is written ?'. The buyer wants to read the message segment by segment.

One line, split into segments

lines: true reads the message as one line. split-row cuts it on the apostrophe, with escape: "?" so that ?' stays an apostrophe, and position numbers the segments in message order. regex-extract separates the segment's tag from its elements.

  1. 1
    ?'

    An apostrophe, not a segment end.

What this step proves

A one-line message becomes fourteen segments, no phantom one.

manifests/10-orders.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-edifact-b  connector_type: csv-file  scopes: [purchasing-b]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/edifact-orders/b/*.edi   # one ORDERS message per file  parser:    lines: true                    # the message is one line  after_process: none  mapping:    row:      - split-row: { by: line, sep: "'", escape: "?", position: seg_no }   # one row per segment; ?' is an apostrophe    cell:      - regex-extract:             # the tag, then the segment's elements          column: line          required: true          pattern: "^([A-Z]{3})\\+?(.*)$"          groups: { 1: tag, 2: elements }      - regex-extract: { column: elements, pattern: "^\\d+\\+([^+]+)\\+", groups: { 1: order_no } }   # BGM: the order number      - regex-extract: { column: elements, pattern: "^\\d+\\+\\+(\\d+):EN$", groups: { 1: ean } }    # LIN: the article's EAN      - regex-extract: { column: elements, pattern: "^21:(\\d+)$", groups: { 1: quantity } }        # QTY 21: the ordered quantity      - fill-down: { columns: [order_no], reset-when: { column: tag, in: [UNH] } }      # the order, on every segment of its message      - fill-down: { columns: [ean], reset-when: { column: tag, in: [LIN, UNT] } }      # the EAN, on the segments of its line

Each QTY carries its order and its EAN

Two regex-extract read the order number in the BGM and the EAN in the LIN; fill-down carries them onto the segments that follow. The number starts again at each UNH, the EAN at each LIN and UNT: a QTY always carries its own LIN's EAN, never the previous one's. A filter on the tag then lists the order lines: PO-7001, 3012345000110 × 12 and 3012345000127 × 6.

Limits

  • The order lines are a filtered reading of the segments (--filter tag=QTY): nothing filters after the cell tier.
  • The UNA segment, which declares the separators, goes through the same escape: it reads ":+.".
  • One message per file; fictitious GLN and EAN numbers.
