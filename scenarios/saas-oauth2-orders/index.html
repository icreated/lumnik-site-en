The SaaS behind OAuth2: 30-second tokens, a 40-second run, no page lost.

The ERP no longer moves, but some orders arrive through a recent SaaS. That SaaS no longer takes a fixed token: it hands out a client id and a secret, and wants a short-lived token on every call. lumnik asks for the token, renews it before it expires, absorbs a key rotation in the middle of a run, and says why when the secret is revoked, without ever showing it.

A stored secret, a manifest that names it, a pre-flight

The client secret becomes an lm secret; the manifest only names it with client_secret_env. lm source rest test asks the authorization server for a token and reads the first page, before any run.

What this step proves

The secret is in no file: the manifest names it, the hub resolves it.

200 orders in 40 seconds, with 30-second tokens

The SaaS serves 8 pages of 25 orders, 5 seconds each; its tokens live 30 seconds. lumnik keeps the token between pages and asks for a new one shortly before it expires: no page is refused.

    8 pages

    200 orders read, 200 written.

  2. 2
    No 401

    The token is renewed before it ends.

One refusal, a fresh token, the same page read again

After page 2 the SaaS revokes every token, as a key rotation would. Page 3 is refused once; lumnik asks for a fresh token and reads the same page again. The run completes with nothing lost.

    One 401

    Then one fresh token, once.

    The original request, signed again.

invalid_client: said at the pre-flight and on the run

The client secret is changed on the SaaS. lm source rest test and the run say the same sentence: the authorization server refuses, with its standard error code. Neither the secret, nor the token, nor the server's free-text description appears in what lumnik shows.

  1. 1
    invalid_client

    The server's code, nothing else.

  2. 2
    No secret

    Not in the outputs, not in the evidence.

Limits

  • Client credentials only: no browser sign-in, no refresh token, no mTLS.
  • A token under 8 characters is refused: too short to be told from the data the source sends back.
  • Simulated SaaS, synthetic orders.
