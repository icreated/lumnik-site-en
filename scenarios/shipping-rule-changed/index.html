The rule changed on 1 January: every order says which version computed it.

The shipping fee is computed by a Kotlin script the hub's operator provides: free shipping from 150.00 in December, from 200.00 from January. The operator replaces the script. Months later, an auditor asks why an order of 172.50 shipped free in December and paid shipping in January.

Why the same amount does not ship the same

The entity shows the run that wrote each order. CMD-2402 (December) and CMD-2501 (January) both have 172.50 of goods: shipping 0.00 for one, 12.90 for the other. lm run get on CMD-2402's run names version 1 of the rule.

  1. 1
    _run_id

    The run that wrote the row.

What this step proves

Order, run, version of the rule: the chain reads with lm, without access to the server.

Limits

  • The run lists the versions it applied, not which rows went through which: a script replaced during a run leaves its rows under both versions.
  • A fingerprint identifies a text, not what it says: keeping the script's versions remains the operator's job.
  • Synthetic orders.
