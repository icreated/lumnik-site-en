A marketplace's orders, one line per item to pick: model, colour, size.

The marketplace export gives one line per order, the items packed into one cell, and an item reference that packs model, colour and size in turn. Logistics wants one line per item, to count what to take out of stock. The manifest splits the order, then the reference, and refuses a file whose column was renamed.

What the hub refuses beside split-row

An order split into three items is no longer one row: on-error: dlq would dead-letter fragments, not the order, and validate-row after the split would drop items one by one. lm validate refuses both, with the reason, before anything runs.

A composition that would skew the run's count is never applied.

The export, split on the way in

require-headers checks that order_no and items are there; skip-empty-rows drops the separator line the export adds. split-row makes one row per item and position numbers them; upper writes tsh-vert-s in capitals; split cuts the reference into model, colour and size.

One line per item to pick

Eleven items for seven orders. CMD-1003 orders the same T-shirt twice: item_no 1 and 2 make them two lines. Without position, the two lines would have the same content, and the table keeps only one. CASQ-NOIR has no size: the cell stays empty. SWEAT-BLEU-MARINE-L gives colour BLEU and size MARINE: the value is written as split, and counted.

Limits

  • A colour holding a dash, like BLEU-MARINE, shifts the size: split counts the cell but does not correct it.
  • OUT counts the orders written; the number of items is read in the table.
  • Two identical lines in the file itself land as one row.
  • Synthetic orders.
