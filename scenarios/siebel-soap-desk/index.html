The CRM's SOAP desk: each service read its own way, nothing read twice.

A 2000s CRM exposes its data through custom SOAP web services: a case's actions in one call, a customer's opportunities page by page on a page number. The password travels inside the envelope. lumnik reads each one the way it reads, carries the service's Fault verbatim, and never sends the same request twice.

The envelope as it goes out, the password a secret

Two REST connectors in SOAP shape on the same desk. The header carries the service account the way the CRM expects it; the password is a hub secret, resolved when sending. The pre-flight sends the real request and reads the answer.

The service's Fault on the run, one attempt

The service account's password changed on the CRM side. The run fails with the service's own message; it is not retried, and the CRM sees one request.

  1. 1
    The CRM's message

    With its code, not an "HTTP 500".

  2. 2
    No retry

    A refusal is not fixed by asking again.

Limits

  • A SOAP read is one pass, in memory: lm run cancel only takes effect when the read ends.
  • The service is called for one case and one customer written in the manifest; one call per case of a list is not covered.
  • An incremental import's mark travels in the URL, not in the body: a service that filters by period in its body is read whole.
  • Simulated CRM; synthetic data.
