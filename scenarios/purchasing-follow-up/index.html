"Et SUP-004 ?": a follow-up question, answered as the whole question.

A buyer asks how many orders were cancelled, then "Et pour le fournisseur SUP-003 ?", then "Et SUP-004 ?". Nobody retypes the question. Ask reads each follow-up with the question before it, answers the full question and shows the one it understood.

"Et celle de mardi dernier ?": refused

The follow-up is understood as the orders cancelled last Tuesday. Nothing in the orders answers that: Ask runs no query and says so. In JSON, abstained is true and the SQL is empty.

    No SQL

  2. 2
    abstained: true

What this step proves

A follow-up the data cannot answer is refused, like any question.

Limits

  • The understood question comes from the model configured on the hub (qwen2.5-coder:7b here). The hub checks it before using it; another model may word it differently.
  • lm sends the previous question only when it is given one. The TUI :ask page does not carry it yet (#1406); the PWA chat does.
  • Synthetic orders; one entity, one scope.
