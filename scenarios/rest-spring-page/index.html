A Spring Page: when Spring changes its JSON, one line follows.

Goal Read a Spring Boot app's whole catalogue, page after page, before and after the team changes how its Pages are serialized.

A Spring controller returns the repository's Page. lumnik reads it with a preset:

  • pagination: { kind: spring-page }: 130 articles in 3 requests;
  • the team follows Spring's warning and switches to VIA_DTO: the total moves under page, the same manifest reads everything, one empty page too many;
  • one line, spring-paged-model: 3 requests again.

A Spring controller, 130 articles

Spring Boot 3.4.5, Spring Data JPA. The controller returns the repository's Page as is.

  • content: 50 articles per page
  • totalPages: 3
  • totalElements: 130
  1. 1
    Spring's warning

    Spring logs that this shape is not guaranteed stable, and recommends VIA_DTO.

What this step proves

The answer says how many pages there are.

One line: pagination: { kind: spring-page }

One rest-generic connector.

  • pagination: spring-page: page and size, from 0 up to totalPages
  • key: the article's reference
  1. 1
    3 requests

    page=0, 1, 2, read from Tomcat's access log.

What this step proves

The preset reads Spring's Page as it comes out.

Every article must be read, every night.

Spring Boot 3.4, a lab app

The problem

The app returns its articles in pages.

  • Each page says how many there are.
  • One day, the team changes the shape of that answer.

What is not changed

The app's code stays its own.

  • The controller returns Spring's Page.
  • The serialization is the team's choice.

What had to be written

pagination: { kind: spring-page }

Name the framework.

A 23-line connector: 130 articles, 3 requests.

The change

The team follows Spring's warning.

  • The total moves under page.
  • The hub reads everything, one empty page too many.

The fix

pagination: { kind: spring-paged-model }

One line changes.

  • 3 requests again.
  • 130 articles, one row each.

The limit

A lab app, not a published product.

  • Written with Spring's own classes.
  • Without the right preset, nothing is lost: one request too many.
