PrestaShop: the XML catalogue read in one line

Goal Read every product of a PrestaShop 8 shop through its Webservice, in XML, as it answers.

A real PrestaShop 8.2.8 and its demo catalogue. Its Webservice answers XML.

  • not told, the hub refuses the XML and says what to add;
  • response_format: xml: the hub reads the XML; PrestaShop ignores offset=, and the repeated page is refused;
  • pagination: { kind: prestashop }: the 19 products, their name read from the XML.

PrestaShop 8 and its XML Webservice

The official image, installed unattended, with its demo catalogue. The Webservice is switched on with a read-only key, drawn at each replay.

  • it answers XML: text/xml
  • offset=0 and offset=5 return the same products
  • limit=5,5 returns the next ones

    Its own pagination

Limits

  • An XML document that declares a DTD or an entity is refused: lumnik never reads one.
  • Values arrive as text: the price is promoted as decimal to compare it.
  • PrestaShop's demo catalogue: 19 products; a throwaway key, drawn at each replay.

E-commerce · catalogue

The catalogue lives in PrestaShop.

Every product must be read, every night.

PrestaShop 8.2.8, its demo catalogue

The problem

PrestaShop answers XML.

  • Not JSON, like most APIs.
  • And it pages its own way: limit=0,50.

What is not changed

The shop stays as it is.

  • Its Webservice, a read-only key.
  • No module, no setting.

The first try

The hub refuses XML it was not told about.

  • It never reads zero products in silence.
  • It says the word to add.

What had to be written

response_format: xml
pagination: { kind: prestashop }

Two lines.

  • 19 products out of 19, name and price.
  • A 25-line connector.

What was fixed

Three gaps found, three fixes.

  • The hub reads XML.
  • A repeated page fails the read.
  • The prestashop preset.

The limit

XML read safely.

  • No DTD, no entity: refused.
  • Values arrive as text.
