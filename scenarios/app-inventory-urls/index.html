An application inventory with hand-typed URLs

Goal Split each URL into server, port and environment, to know what runs on a server and what is still in staging.

IT takes over an application inventory kept for years in a spreadsheet.

The URL column is typed by hand:

  • mixed upper and lower case;
  • stray spaces around it;
  • a port sometimes there, sometimes not.

The manifest splits the URL into columns, without code.

The URL split into columns

The connector reads the spreadsheet as is.

  • filter-where: keeps active applications only
  • clean: strips the spaces pasted around the URL
  • lower: SRV-ERP-PRD01 and srv-erp-prd01, one server
  • regex-extract: takes scheme, server and port from the URL, then the environment from the server name
  • default: a server off the convention gets hors-convention
  • lookup: prd, rec, dev become production, recette, développement

Limits

  • regex-extract does not count a miss: a pattern that does not read a line leaves its columns empty without warning, and a default downstream may fill them.
  • default fills a constant: a protocol's port is not inferred.
  • Synthetic inventory.

The problem

A URL is not a column.

  • SRV-ERP-PRD01 and srv-erp-prd01.
  • Stray spaces.
  • A port sometimes there, sometimes not.

Nothing is changed

The spreadsheet stays as is.

  • lumnik reads each URL.
  • It splits it: server, port, environment.
  • Retired applications are dropped and counted.

What it took to write

- lookup:
    column: environment

             rec: recette }

The server name tells the environment.

The answers

IT's questions, one filter each.

  • srv-erp-prd01: ERP and PORTAIL.
  • In staging: CRM and QUALITE.
  • Off the convention: INTRANET and EDI.

The limit

A pattern that misses a line does not say so.

  • EDI, in ftp://, has no server.
  • A protocol's port is not guessed.
