The carrier reads its cursor from a header: sent elsewhere, the run fails instead of lying.

Goal Read every tracking event of a carrier whose API expects the page cursor in a request header.

A carrier's tracking API pages by cursor. It reads it from the X-Next-Cursor header, and nowhere else:

  • sent as a query parameter, the default, the cursor never arrives: the API returns the first page and says there are more; the run fails and says why;
  • one line, cursor_binding: header, and the 1,200 events go through, 12 pages.

1,200 events, the cursor in a header

A carrier API, simulated for the replay: 1,200 tracking events, 100 a page.

  • has_more: there are more pages
  • next_cursor: the next page's cursor
  • the next page is asked for by the X-Next-Cursor header; anywhere else, the cursor is ignored

Cursor as a query parameter: the run fails

The connector sends the cursor as a query parameter, the default. The API ignores it and returns the first page, with the same cursor. lumnik refuses to stop there: the run fails and names the keys to check.

Limits

  • The refusal recognises a source that sends back the cursor it was just given. A source returning random pages would not be recognised.
  • Without a total published by the API, no witness compares the count read with the real one.
  • Simulated carrier API, synthetic events.

Transport · parcel tracking

The carrier publishes 1,200 tracking events.

The import must read them all, page after page.

Simulated carrier API

The problem

The API expects the next page in a header.

  • Sent elsewhere, it is ignored.
  • The API then returns the first page.
  • It still says there is more.

What is not changed

The API stays as it is.

  • A carrier token, stored with lm secret.
  • No work on the carrier's side.

What had to be written

cursor_binding: header
cursor_param: X-Next-Cursor

Say where the cursor goes.

  • 300 parcels, each at its latest status.
  • The cursor goes in the header on every page.

The limit

The refusal relies on the API repeating its page.

  • An API returning random pages would not be recognised.
  • The count's witness is the total the API publishes, if it publishes one.
