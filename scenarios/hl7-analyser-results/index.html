HL7 v2: the analyser result above its range, flagged or not

Goal Read the HL7 v2 messages two analysers drop for the LIMS, and be told when a result is above its reference range.

Two chemistry analysers, HL7 v2.5.1 ORU^R01: segments ended by a lone carriage return.

  • csv-file reads one segment per row, MSH, PID, OBR, OBX;
  • the sample is carried down onto each result;
  • a Process compares the value with the range sent beside it, whatever the flag.

Two analysers, eight messages a batch

Each sample is one message. Each segment ends with a lone carriage return, \r.

  • MSH: the analyser and the message id
  • PID: the sample and its lot
  • OBX: one result, its unit, its range, its flag

One segment per row, the sample on every result

lines: true reads a segment per row: the lone \r ends one. A regex per segment type cuts its fields.

  • fill-down carries the analyser and the sample onto the OBX rows
  • reset-when: MSH, a new message starts empty
  • parse-number, parse-date
  1. 1
    Every segment stays

    MSH, PID and OBR are rows too: a filter runs before fill-down, never after. The rule reads segment=OBX.

What this step proves

An HL7 message becomes rows a rule can read, without an interface engine.

manifests/10-analyser-results.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-hl7-a  connector_type: csv-file  scopes: [qc-chem-a]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/hl7-analyser-results/a/*.hl7   # the folder the analysers drop their batches in  parser:    lines: true                    # one segment per row; HL7's lone carriage return ends a segment  after_process: none  mapping:    cell:      - regex-extract: { column: line, pattern: "^([A-Z][A-Z0-9]{2})\\|", groups: { 1: segment } }      # MSH: the analyser (MSH-3) and the message's control id (MSH-10)      - regex-extract: { column: line, pattern: "^MSH\\|[^|]*\\|([^|]*)\\|(?:[^|]*\\|){6}([^|]*)\\|", groups: { 1: analyser, 2: message_id } }      # PID: the sample (PID-3, first component) and the lot (PID-5)      - regex-extract: { column: line, pattern: "^PID\\|[^|]*\\|\\|([^^|]*)[^|]*\\|\\|([^|]*)", groups: { 1: sample, 2: lot } }      # OBX: the test, the value, the unit, the reference range, the flag, the time of observation      - regex-extract:          column: line          pattern: "^OBX\\|(\\d+)\\|NM\\|([^^|]*)\\^([^|]*)\\|\\|([^|]*)\\|([^|]*)\\|([^-|]*)-([^|]*)\\|([^|]*)\\|(?:[^|]*\\|){5}(\\d{14})"          groups: { 1: obx_seq, 2: test_code, 3: test_name, 4: value, 5: unit, 6: range_low, 7: range_high, 8: flag, 9: observed_at }      # the message's analyser and sample, on every segment of the message      - fill-down: { columns: [analyser, message_id, sample, lot], reset-when: { column: segment, in: [MSH] } }      - parse-number: { column: value }      - parse-number: { column: range_low }      - parse-number: { column: range_high }      - parse-date: { column: observed_at, formats: ["yyyyMMddHHmmss"] }

The range, not the flag

The Process compares each result with the range the analyser sent beside it.

  • segment=OBX: results only
  • "value>{range_high}": two columns of the row
  • key: sample, the decision carries the sample
  1. 1
    Applied after the first batch

    A Process judges new rows only. The first batch is all in range.

What this step proves

A rule holds even when the analyser's flag is missing.

Limits

  • The table holds every segment: a View or a rule reads segment=OBX. No hook drops a row after fill-down.
  • Conditions are ANDed: below the range is a second Process.
  • Only NM results are read; a text (ST) or coded (CE) OBX keeps its line without columns.
  • Files, not MLLP: the analysers write to a folder, the hub does not listen on a socket.
  • Synthetic samples, lots and results.

Laboratory · HL7 v2

The analysers speak HL7 v2.

One message per sample, one segment per line.

ORU^R01, MSH · PID · OBR · OBX

The problem

One analyser sends no flag.

  • Its creatinine at 162 µmol/L goes unnoticed.
  • The range was in the message all along.

What is not changed

The analysers stay as they are.

  • Their HL7 files, in their folder.
  • No interface engine, no code.

What had to be written

fill-down: { columns: [sample], reset-when: MSH }
when: [segment=OBX, "value>{range_high}"]

One regex per segment, one condition.

  • csv-file: the segments as rows.
  • A Process: the range, not the flag.

The result

Two decisions, one without a flag.

  • Lactate 3.1, flagged H.
  • Creatinine 162, flag empty.
