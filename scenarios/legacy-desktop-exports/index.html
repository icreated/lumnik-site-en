One machine register spread across three legacy databases

Goal Bring three workshops' OpenEdge, FoxPro and Access exports together in one machine register, each read in its own format and encoding, and see the only machine where two registers disagree.

An industrial group has three workshops, and each keeps its machines in its own desktop database, installed twenty or thirty years ago.

  • Nord exports from Progress OpenEdge, Est from FoxPro for DOS, Sud from Access;
  • each format asks for its gesture: ? for unknown, -1 for yes, a midnight time, a two-digit year;
  • FoxPro's export, read without its code page, is guessed as windows-1252: the run says so and stops on the É of "Électroérosion";
  • together, the three registers make 17 machines and one dispute: the grinder that moved from Est to Sud.

Three registers, three exports

Each workshop exports its register the way its database can.

  • Nord, Progress OpenEdge, the EXPORT statement: space-separated, ISO-8859-1
  • Est, FoxPro 2.6 for DOS, COPY TO … DELIMITED: comma, code page 850
  • Sud, Access, the text export wizard: semicolon, a header line, windows-1252

OpenEdge: ? for unknown, a two-digit year

The csv-file connector, space-separated, strings in quotes.

  • regex-replace: ? is OpenEdge's unknown value, emptied before it is typed
  • parse-date MM/dd/yy, century-from: 1950: 09/17/79 is 1979, not 2079
  • yes/no is a boolean, the notes over two lines stay whole
  1. 1
    Without the regex-replace

    parse-date does not read ?: the cell is emptied all the same, but counted as an error. M-1104, received without a log book, has no known service or contract.

What this step proves

An unknown value arrives empty, not as an error.

FoxPro without its code page: the run says so

The connector declares no encoding. The hub guesses windows-1252, 26% sure.

  • the first four lines are read, accents wrong: Hur‚, Perceuse … colonne
  • the fifth holds É, the byte 0x90, which windows-1252 leaves undefined: the file stops there
  • the run ends Partial; its note and the dead letter name the encoding, the byte and the line
  1. 1
    Two signals

    The note says the encoding was guessed (#1885). The dead letter says which byte has no character, and on which line (#1887).

Access: -1 for yes, midnight, the decimal comma

Access's text export wizard writes its own way.

  • a date is written 14/03/2019 00:00:00: the format with ' 00:00:00' as a literal gives a date, not midnight UTC
  • Yes/No is written -1/0: parse-boolean declares it
  • 47000,00 is a number, the memo keeps its two lines
  1. 1
    The column names

    Libellé, Révision: Access's header gives its accented names, and the entity takes them as they are.

Limits

  • A memo cut at the source does not show: Access cuts a memo at 255 characters on export (M-3303), FoxPro COPY TO does not export memos. The hub reads what it receives.
  • A guessed code page stays a guess: the hub flags a file that looks like a DOS page read as windows-1252, not every encoding error.
  • After a wrong encoding, the file is read again with lm endpoint reset-cursor; the connector does not read it again on its own.
  • The hub has no jdbc-generic dialect for OpenEdge, FoxPro or Access: only their exports are read.
  • lm entity get's table shifts on a memo over several lines (#1889); the page shows the register through SQL.
  • Machines, dates and values synthetic; the export formats are reproduced, not produced by the software itself.

Maintenance · three workshops

Three workshops, three legacy databases.

OpenEdge at Nord, FoxPro for DOS at Est, Access at Sud. None will be migrated.

machines.d · MACHINES.TXT · Machines.txt

The problem

FoxPro writes CP850. The hub guessed windows-1252.

  • Huré became Hur‚, without a word.
  • The É of "Électroérosion" stopped the file at line 0.

What is not changed

The three databases stay as they are.

  • Their exports are the ones they can make.
  • No file edited, no ODBC driver.

What had to be written

encoding: IBM850

One line in the FoxPro connector.

  • Then lm endpoint reset-cursor.
  • Est's six machines, accents right.

What was fixed

A guessed encoding is said (#1885).

  • A byte with no character is named, with its line (#1887).
  • 17 machines, one dispute: M-2206.
