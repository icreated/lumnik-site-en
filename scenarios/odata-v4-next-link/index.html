OData v4 paged by the server: lumnik follows @odata.nextLink

Goal Read the 120 customers of an OData v4 service paged by the server, as Business Central pages, in pages of 20 asked with Prefer, without losing one.

Business Central pages its OData answers on the server, and a client asks for smaller pages with Prefer: odata.maxpagesize. The next page is not a parameter the client computes: it is @odata.nextLink, a URL the server hands back.

  • a real ASP.NET Core OData v4 service
  • the odata-v4 preset, the $count total as witness
  • six pages of 20, 120 customers
  • lumnik Open
  • ERP
  • API
  • Microsoft

1 · Readodata-v4 + Prefer

Six pages of 20, 120 customers

The ASP.NET Core OData service pages at 50. The connector asks for 20 per page and follows the server's links.

  • kind: odata-v4, where the rows, the next link and the total sit
  • $count=true: the total the run checks
  • Prefer: odata.maxpagesize=20, declared once, sent on every page
  1. 1
    Counted by the server

    Its log shows six GETs, $skip 0 to 100.

  2. 2
    Counted by lumnik

    The run says IN 120, OUT 120.

What this step proves

The server decides the pages, lumnik follows the link it hands back.

manifests/10-customers.yaml
apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-odata-customers-a  connector_type: rest-generic  scopes: [finance-a]spec:  base_url: http://host.docker.internal:18073  headers:    # Business Central pages at 20,000 by default; a client asks for smaller pages, as Microsoft documents.    - { name: Prefer, value: odata.maxpagesize=20 }  endpoints:    - id: customers      method: GET      path: /odata/Customers?$count=true    # $count: the total the run checks itself against      pagination: { kind: odata-v4 }        # @odata.nextLink, value, @odata.count      target:        kind: hybrid        table: connector.scenario_odata_customers_a        unique_key: $.Id        promote:          - { name: customer_no, path: $.No, type: text }          - { name: name, path: $.Name, type: text }          - { name: city, path: $.City, type: text }          - { name: balance, path: $.Balance, type: decimal }

Limits

  • This is not Business Central: it is the OData framework Microsoft publishes, paging the same way. Business Central's OAuth2 authentication is not shown here.
  • A server may ignore Prefer: the page size is then its own, and the run still follows the link.
  • 120 synthetic customers.
