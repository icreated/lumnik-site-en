A flat EDI file from an ERP: fixed-width order lines, read without a mapping tool.

A manufacturer exchanges flat files with its logistics partner, one folder per partner, one prefix per exchange type. No separator: every field has its place and its width, a header line first, ISO-8859-1, and sometimes no line end after the last line. The partner wants the order lines as columns.

The file read line by line, the header set aside

lines: true reads one line per record, guessing no separator. filter-where keeps the lines that carry a customer code and sets the header aside, counted. regex-extract cuts eleven fields at their place and width; clean removes the padding; parse-number reads 30.000.

  1. 1
    Widths

    17, 10, 10, 40, 50… one expression.

  2. 2
    End of file

    The last line, with no line end, is read.

apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-edi-cc-b  connector_type: csv-file  scopes: [logistics-b]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/edi-flat-order-lines/b/ZINT_CC_*.txt   # one file per order the ERP sends  parser:    lines: true                        # one line = one row, no separator to guess  after_process: none  mapping:    dataset:      - filter-where: { column: line, regex: ".{27}EC.*" }   # order lines carry a customer code; the header does not    cell:      - regex-extract:                 # every field at its place and width          column: line          required: true          pattern: "^(.{17})(.{10})(.{10})(.{40})(.{50})(.{8})(.{3})(.{12})(.{12})(.{40})(.{10})(.{4})(.*)$"          groups: { 3: customer, 4: customer_name, 5: address, 6: postcode, 7: country, 8: order_no,                    9: article, 10: label, 11: quantity, 12: unit, 13: line_id }      - clean: { columns: [customer, customer_name, address, postcode, country, order_no, article, label,                           quantity, unit, line_id], strip: true }      - parse-number: { column: quantity, decimal-separator: "." }

The order lines as columns

Customer, delivery address, order, article, label, quantity and unit. ISO-8859-1 accents land right: "Couverture à barres". The label stays cut at 40 characters, as the ERP wrote it.

Limits

  • The widths are the file's: if the ERP changes its layout, the expression changes with it.
  • A label the ERP cut stays cut: lumnik does not recover what was not sent.
  • Synthetic files, on the template of a real exchange.
