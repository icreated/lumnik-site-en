A semicolon in a label breaks one line of the catalogue

Goal Set the unreadable line aside with its values, remove no article while it stays unreadable, then close the dead letter once the export is fixed.

An ERP exports its article catalogue every night. One label holds the separator, unquoted.

  • the line set aside with its raw values;
  • nothing removed from the catalogue while it is unreadable;
  • the dead letter closed by the run that really read it again.

Limits

  • The hub checks that the named run could carry the line (Completed, same connector, after the letter), not that it wrote it.
  • Each night that reads the line again adds a dead letter: they are closed one by one.
  • Synthetic data.

Catalogue · nightly export

The ERP exports its catalogue every night.

One line breaks the format.

Ten articles, three nights

The problem

A « ; » in a label.

  • No quotes.
  • Four values for three columns.

What is not changed

The export stays as it is.

  • No line touched up.
  • No value cut to make it fit.

The trap

Removing what could not be read.

  • The file is the whole table.
  • An unreadable line looks like a missing one.

What had to be written

delimiter: ";"

Nothing more.

  • The unreadable line becomes a dead letter.
  • No removal while it is there.
  • A 14-line scenario, one manifest.

The proof

The letter closed by the right run.

  • Night 2 is refused as proof.
  • Night 3, which wrote A04, is accepted.

The limit

One letter per night.

  • Each night that reads the line adds one.
