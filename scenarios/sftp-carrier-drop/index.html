The carrier's SFTP drop read every night with nothing taken on trust

Goal Read the carrier's file every night, file it away, and refuse a server whose key changed.

A carrier drops livraisons.csv on its SFTP every night, always under the same name.

  • each night read, then archived under its name and time;
  • a file not archived said on the run;
  • a changed server key refused until confirmed.

Limits

  • The check before a move is not atomic with it: a file dropped in the milliseconds between them is still moved.
  • A carrier that writes under another name and renames it in is never caught in that window.
  • Simulated SFTP server; synthetic data.

Transport · SFTP

The carrier drops a file every night.

Always under the same name.

Four nights, simulated server

The problem

Same name, same size.

  • One night can look like the last.
  • One archive can overwrite another.

What is not changed

The carrier's server stays as it is.

  • Its drop folder.
  • Its SFTP account.

The trap

Talking to the wrong server.

  • The server is reinstalled.
  • Its key is no longer the same.

What had to be written

host_key_fingerprint: "SHA256:…"

One line.

  • The hub only talks to the known server.
  • Each night archived under its time.
  • A 20-line scenario, one manifest.

A refusal

The key changed: refused.

  • Both fingerprints named.
  • Confirm with the carrier, then pin.

The limit

A drop during the move.

  • A few non-atomic milliseconds.
