Drupal speaks JSON:API: name the standard, one line reads the whole site.

Goal Read every article of a Drupal site through its JSON:API module, without writing the paging.

Drupal 11 exposes its content through JSON:API, a core module. The next page is in links.next, which Drupal writes as an object {"href": …}. lumnik has a preset for that standard:

  • pagination: { kind: json-api }, and the 5 pages are followed;
  • 45 articles read, 45 written to the hub.

A real Drupal 11, JSON:API on

Drupal 11.4 on SQLite, installed with drush. 45 articles. The JSON:API module, in Drupal core, answers:

  • data: the page's articles
  • links.next: the next page, written as an object {"href": …}
  • page[limit], page[offset]: the standard's paging
  1. 1
    The link object

    The JSON:API specification accepts a link as a string or as an object with href; Drupal writes the object.

One line: pagination: { kind: json-api }

One rest-generic connector.

  • pagination: json-api: follows links.next, reads data
  • fields[node--article]: only the fields needed are asked for
  • unique_key: the article's JSON:API id

Limits

  • The hub reads what the API publishes: unpublished content is not read without an account.
  • Drupal publishes no total by default: no witness compares the count read with the real one.
  • Before icreated/lumnik#1638, the json-api preset failed on a link object; this page's replay runs on a fixed hub.

The problem

Every API pages its own way.

  • Writing the paging by hand is a source of errors.
  • Drupal follows a standard: JSON:API.

What is not changed

Drupal stays as it is.

  • Its core JSON:API module, switched on.
  • No module added, no code.

What had to be written

pagination: { kind: json-api }
