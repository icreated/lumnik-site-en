A CFONB 120 bank statement: each movement signed, in its statement, with its complements.

French banks still send account statements as CFONB 120 files: fixed-width records of 120 characters, no separator. 01 opens a statement with its old balance, 04 is a movement, 05 completes the movement before it (payer, invoice reference), 07 closes with the new balance. The amount's last character carries both its last digit and its sign. Treasury wants each movement signed, in its statement, with its complements.

Records of 120 characters, cut by position

lines: true reads each record as one line. regex-extract cuts the fields at their positions: code, account, date, label, amount, and for a 05 its qualifier and its complement. An operator's Kotlin script reads the sign from the amount's last character ({ and A to I positive, } and J to R negative), parse-number makes it a number.

apiVersion: connectors.lumnik.io/v1kind: Connectormetadata:  name: scenario-cfonb-b  connector_type: csv-file  scopes: [treasury-b]spec:  transport:    kind: local    path: /tmp/lumnik-scenario/cfonb-bank-statement/b/*.txt   # the bank's CFONB 120 statements  parser:    lines: true                    # fixed width: 120 characters per record, no separator  after_process: none  mapping:    cell:      - regex-extract:             # every record: its code, then the account it is about          column: line          required: true          pattern: "^(\\d{2})(.{5}).{4}(.{5})(.{3})(\\d).(.{11})"          groups: { 1: record, 2: bank, 3: branch, 4: currency, 5: decimals, 6: account }      - regex-extract:             # 01 old balance, 04 movement, 07 new balance          column: line          pattern: "^0[147].{32}(.{6}).{8}(.{31}).{2}(.{7}).{2}(.{14})"          groups: { 1: op_date, 2: label, 3: entry_no, 4: amount_raw }      - regex-extract: { column: line, pattern: "^05.{43}(.{3})(.{70})", groups: { 1: qualifier, 2: info } }   # 05 complement      - regex-extract: { column: line, pattern: "^01.{32}(.{6})", groups: { 1: statement_date } }              # 01 opens a statement      - regex-extract: { column: line, pattern: "^04.{79}(.{7})", groups: { 1: movement } }                    # 04 is a movement      - clean: { columns: [label, info, entry_no], strip: true }      - kotlin: { script: hooks:cfonb-amount-b.kts }                   # the signed amount, from its last character      - parse-number: { column: amount }      - parse-date: { column: op_date, formats: ["ddMMyy"] }      - parse-date: { column: statement_date, formats: ["ddMMyy"] }      - fill-down: { columns: [statement_date] }                                        # the statement, on each of its records      - fill-down: { columns: [movement], reset-when: { column: record, in: ["01", "07"] } }   # the movement, on its 05 complements
manifests/cfonb-amount.kts
// Operator-provided: a CFONB 120 amount. 13 digits, then one character holding the last digit and the sign —// "{" and A to I for 0 to 9 positive, "}" and J to R for 0 to 9 negative — scaled by the record's decimals.@Suppress("UNCHECKED_CAST")val cells = bindings["cells"] as MutableMap<String, Any?>val raw = (cells["amount_raw"] as String?).orEmpty()if (raw.length == 14) {    val positive = "{ABCDEFGHI".indexOf(raw.last())    val negative = "}JKLMNOPQR".indexOf(raw.last())    val digit = if (positive >= 0) positive else negative    if (digit >= 0) {        val scaled = (raw.dropLast(1) + digit).toBigDecimal().movePointLeft((cells["decimals"] as String).toInt())        cells["amount"] = (if (negative >= 0) scaled.negate() else scaled).toPlainString()    }}

Each movement, signed, in its statement

fill-down carries the 01's date onto every record of its statement; the second 01 replaces it. A filter on the code lists the movements, each with its signed amount and its statement's date. The balances check out: 1,250.00 − 84.50 + 1,200.00 − 36.20 = 2,329.30.

The payer and the invoice, on the transfer they complete

A 05 does not carry the number of the movement it completes. fill-down carries each 04's number onto the 05 records after it, and forgets it at each 01 and 07. Transfer 0000102 thus finds its payer, MARTIN SARL, and its invoice, F-2026-118.

Limits

  • The sign is decoded by an operator's Kotlin script: no shipped hook reads an overpunched amount.
  • A movement's complements are a filtered reading (--filter movement=…); nothing folds them into one row.
  • Synthetic file; fictitious bank, account and payers.
