A partner demands the catalogue in its own format

Goal Deliver the product catalogue to a partner in the format it imposes, with no conversion code.

Two CSV files from an ERP, products and categories, are joined in the hub and delivered to S3 in a partner's format.

  • French headers, semicolons, decimal commas
  • recoded statuses, masked internal reference
  • a receipt proves the delivered bytes

Products and categories, as the ERP exports them

40,233 products and 63 categories arrive from the ERP. Cleaning happens on the way in.

  • codes upper-cased, text normalised
  • Y/N turned into 1/0
  1. 1
    Envelope

    enrich-context adds ARTICLE, COMPIERE, the catalogue version and date to every row.

  2. 2
    Conservation

    IN = OUT for both sources: no row set aside.

What this step proves

Both files are read in full and cleaned once, on the way in.

Every product carries its category

  • key: m_product_category_id
  • one line per item, category included

    Join

    Check

The partner's format is declared, not coded

The Export declares the partner's format, column by column.

  • renamed headers
  • version and date formatted, statuses recoded
  • category reference masked, active categories only
  1. 1
    S3 keys

    Both keys go through stdin into hub secrets, never into argv or the manifest.

  2. 2
    Receipt

    The hub records the row count, the byte count and the SHA-256 of the delivered object.

What this step proves

An export run leaves a verifiable receipt.

Limits

  • Masking a predictable identifier is pseudonymisation, not encryption; if the partner must not correlate categories, drop the column.
  • Snapshot mode rewrites the whole object on every run.
  • Synthetic data.

Catalogue · partner

A partner wants the catalogue.

In its format, not ours.

Semicolons, decimal commas, its own headers and codes.

Synthetic catalogue

The problem

One conversion script per partner.

  • The ERP exports products and categories separately.
  • The partner wants one line per item, category included.
  • Its statuses and dates are not the ERP's.

Nothing is changed

The ERP exports as before.

  • Two CSV files, as they are.
  • The hub joins and formats.
  • No script to maintain.

What had to be written

- name: category_id
  as: REF_CATEGORIE
  format:
    - mask: { keep-last: 4 }

The internal reference is masked.

A 149-line scenario, four declaration files.

What the partner receives

38,300 items, in its format.

  • Renamed headers.
  • Version 1,50 and date 15/10/2026.
  • Status A or I, reference ***0018.

The proof

The receipt states the delivered bytes.

The runner reads the object back from S3: same size, same SHA-256.

Replay of 3 November 2026.

The limit

Masking is not encryption.

  • A masked identifier can still be correlated.
  • If the partner must not correlate, drop the column.
  • Snapshot mode rewrites the whole object.
